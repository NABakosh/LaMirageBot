# 🔥 CONTEXT: Полная Документация Бота La Mirage Beauty

*Этот файл содержит исчерпывающее описание функционала бота, составленное на основе полного анализа кода `main.js`. Используйте этот документ как контекст при внесении любых изменений.*

## 1. Архитектура Системы

### Технический Стек
*   **Платформа**: Node.js.
*   **WhatsApp**: Библиотека `@whiskeysockets/baileys` (WebSocket подключение, эмуляция Web-версии).
*   **База Данных**: PostgreSQL (библиотека `pg`). Используется пул подключений.
*   **Искусственный Интеллект**:
    *   **Провайдер**: Google Vertex AI (`@google-cloud/vertexai`).
    *   **Модель**: `gemini-2.5-flash`.
    *   **Авторизация**: Файл ключа `vertex_key.json` (Service Account). *Критично для обхода региональных блокировок (Казахстан).*
*   **Календарь**: Google Calendar API (Service Account).
*   **Планировщик**: `node-cron`.

### Конфигурация
*   Основные настройки загружаются из `.env` (БД, ключи, список админов).
*   Массив `ADMIN_WHITELIST` определяет номера с доступом к админ-панели.

## 2. Ключевые Процессы (Workflow)

### 2.1. Валидация и Регистрация Клиента
При входящем сообщении:
1.  **Проверка регистрации**: Поиск по `user_id` (с поддержкой маппинга `@lid` ↔ `@c.us`).
2.  **Если клиент новый**:
    *   Запускается сценарий `asking_name_and_phone`.
    *   **Валидация Имени**: Vertex AI проверяет, что это имя (не "привет", не цифры).
    *   **Валидация Телефона**: Vertex AI нормализует номер (7XXXXXXXXXX). Fallback на Regex, если AI недоступен.
    *   После успеха данные сохраняются в табл. `clients`.

### 2.2. Умный Диалог (AI Mode)
Основной режим работы.
*   **Системный Промпт**: Генерируется динамически (`createSystemPrompt`) и содержит:
    *   Текущую дату (Сегодня/Завтра).
    *   Полный прайс-лист, сгруппированный по категориям (Маникюр, Брови, Ресницы) и мастерам (Топ / Стандарт).
    *   Инструкции по ведению диалога ("не использовать markdown").
*   **Проверка Доступности**:
    *   Если клиент выбирает время, AI генерирует скрытую команду `ПРОВЕРИТЬ_ДОСТУПНОСТЬ: мастер=..., дата=...`.
    *   Бот перехватывает ответ, проверяет наличие слотов в БД (`checkAvailability`).
    *   Если занято: Генерирует список свободных слотов (`getAvailableSlots`: проверка каждого часа) и подменяет ответ AI.

### 2.3. Создание Записи (Booking Engine)
Специальный механизм `detectBookingIntent` анализирует каждое сообщение.
*   **Условие создания**: В диалоге должны быть явно согласованы **Услуга, Мастер, Цена, Дата, Время** (JSON `ready: true`).
*   **Логика защиты**:
    *   **Rate Limiting**: Макс. 5 попыток создания в час от одного юзера.
    *   **Deduplication**: Защита от создания дубликата записи в течение 5 минут.
*   **Транзакция (ACID)**:
    1.  `BEGIN`.
    2.  `SELECT ... FOR UPDATE` (Блокировка слота).
    3.  Проверка пересечений времени (`OVERLAPS`) с учетом длительности конкретной услуги (`duration`).
    4.  `INSERT` записи со статусом `confirmed`.
    5.  `COMMIT`.
*   **Результат**: Мгновенное авто-подтверждение. Клиент получает детали, админы — уведомление, событие добавляется в Google Calendar.

### 2.4. Отмена Записи
*   Бот ищет ключевые слова ("отмени", "не приду") через `detectCancellation`.
*   Последняя активная запись (`pending` или `confirmed`) переводится в статус `cancelled`.

### 2.5. Управление Сессией
*   Тайм-аут: 30 минут неактивности.
*   Фоновый воркер (cron каждые 15 мин) очищает контекст старых диалогов (`resetSession`), чтобы бот не "зависал".

## 3. Функционал Администратора
Доступен только для номеров из `ADMIN_WHITELIST`.

### Режим "Live Agent" (Оператор)
*   Команда `/connect [номер]` устанавливает мост между админом и клиентом.
*   AI отключается для клиента (`is_admin_mode = TRUE`).
*   Сообщения пересылаются в обе стороны (Admin ↔ Client).
*   `/close` завершает сессию оператора.
*   Триггер вызова: Если клиент пишет "позови оператора/админа", админы получают уведомление с подсказкой `/connect`.

### Команды Управления
*   `/admin`: Отчет по выручке и записям (общий + по мастерам).
*   `/dashboard`: Ссылка на Web UI.
*   `/update_name [имя]`: Принудительная смена имени клиента (или своего).
*   `/cancel [id]`: Ручная отмена записи.

## 4. База Данных и Таблицы
*   **`bookings`**: Основная таблица. Хранит статус, длительность, флаги напоминаний.
*   **`conversations`**: "Память" бота. `history` хранит JSON последних 10 смс. `stage` определяет логику.
*   **`clients`**: CRM. `total_visits`, `total_spent` обновляются автоматически при успешных записях.
*   **`statistics`**: Кэшированная статистика по мастерам.
*   **`booking_logs`**: Аудит всех действий.

## 5. Система Напоминаний (Cron)
Запускается каждые 30 минут (`startReminderScheduler`).
1.  **Напоминание за 24 часа**: Ищет записи, где `NOW + 24h` попадает в окно записи. Ставит флаг `reminder_24h_sent`.
2.  **Напоминание за 2-3 часа**: Ищет записи, где `NOW + 2h` попадает в окно. Ставит флаг `reminder_3h_sent`.
